🔴 CRITICAL ISSUE IDENTIFIED
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
Your current code uses Java hashCode() to encode categorical features:

    ❌ connLog.getIdOrigH().hashCode()  // IP "192.168.1.1" → -1234567890
    ❌ connLog.getProto().hashCode()    // "tcp" → 114799
    ❌ connLog.getService().hashCode()  // "https" → 99162322

WHY THIS IS WRONG:
  • Hash codes are random meaningless integers
  • Different values can produce same hash (collisions)
  • Not reproducible across JVM instances
  • Can be negative (breaks ML assumptions)
  • Zero semantic meaning for machine learning

IMPACT ON YOUR SYSTEM:
  • Poor anomaly detection accuracy
  • Model cannot learn meaningful patterns
  • Inconsistent results across restarts
  • Wasted computational resources

✅ SOLUTION DELIVERED

Implemented proper ML feature encoding based on academic research:

  ✅ IP Addresses: 4 normalized octets + private flag (not hash!)
  ✅ Protocols: Label encoding (tcp=0.25, udp=0.5, icmp=0.75)
  ✅ Services: One-hot encoding (http/https/dns/ssh/ftp/...)
  ✅ Connection States: Semantic label encoding (S0/S1/SF/...)
  ✅ Numerical Features: Log-scaling and normalization
  ✅ Derived Features: Ratios, rates, throughput, symmetry
  ✅ Temporal Features: Hour, day, minute, night patterns
